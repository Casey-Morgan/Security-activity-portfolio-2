# B25 - Design and Implement a Threat Intelligence Module

## Topic

A simple Indicator of Compromise (IOC) threat intelligence module.

## Overview

This activity designs and implements a small threat intelligence module. The module stores known suspicious indicators, checks sample security logs against those indicators, and produces a simple risk-based result.

Threat intelligence helps defenders understand known malicious or suspicious activity. It can include IP addresses, domains, file hashes, URLs, malware names, attacker tactics, and vulnerability information.

This implementation is a safe educational prototype. It does not connect to live threat feeds, block real traffic, or scan external systems. It only checks sample data in a controlled local environment.

---

## Purpose of the Module

The purpose of this module is to demonstrate how threat intelligence can support defensive cybersecurity.

The module can:

- store known suspicious indicators;
- compare log entries with those indicators;
- identify matches;
- assign a severity level;
- produce a short alert summary;
- help prioritise investigation.

---

## Threat Intelligence Concept

An Indicator of Compromise is a clue that may suggest suspicious or malicious activity.

Examples include:

| IOC Type | Example |
|---|---|
| IP address | A known malicious command-and-control server |
| Domain | A phishing domain |
| URL | A malicious download link |
| File hash | A known malware file |
| Email sender | A suspicious sender used in phishing |

This module uses simple example IOCs for learning purposes only.

---

## Module Design

The module has three main parts:

| Component | Purpose |
|---|---|
| IOC database | Stores suspicious indicators |
| Log checker | Compares sample logs against the IOC database |
| Alert output | Shows matched indicators and severity |

The design follows this flow:

```text
Sample log entry -> IOC comparison -> Match found -> Severity assigned -> Alert generated
```

## Implementation Code

```python
ioc_database = {
    "malicious_ips": {
        "203.0.113.10": "High",
        "198.51.100.23": "Medium"
    },
    "suspicious_domains": {
        "fake-login-example.com": "High",
        "update-account-example.net": "Medium"
    },
    "malicious_hashes": {
        "44d88612fea8a8f36de82e1278abb02f": "High"
    }
}

sample_logs = [
    {
        "timestamp": "2026-05-22 10:15:00",
        "source_ip": "192.168.1.20",
        "destination_ip": "203.0.113.10",
        "domain": "normal-site.example",
        "file_hash": ""
    },
    {
        "timestamp": "2026-05-22 10:20:00",
        "source_ip": "192.168.1.22",
        "destination_ip": "8.8.8.8",
        "domain": "fake-login-example.com",
        "file_hash": ""
    },
    {
        "timestamp": "2026-05-22 10:25:00",
        "source_ip": "192.168.1.25",
        "destination_ip": "1.1.1.1",
        "domain": "safe-example.com",
        "file_hash": "44d88612fea8a8f36de82e1278abb02f"
    },
    {
        "timestamp": "2026-05-22 10:30:00",
        "source_ip": "192.168.1.30",
        "destination_ip": "8.8.4.4",
        "domain": "university.example",
        "file_hash": ""
    }
]

def check_log_entry(log_entry, iocs):
    alerts = []

    destination_ip = log_entry.get("destination_ip")
    domain = log_entry.get("domain")
    file_hash = log_entry.get("file_hash")

    if destination_ip in iocs["malicious_ips"]:
        alerts.append({
            "type": "Malicious IP",
            "indicator": destination_ip,
            "severity": iocs["malicious_ips"][destination_ip]
        })

    if domain in iocs["suspicious_domains"]:
        alerts.append({
            "type": "Suspicious domain",
            "indicator": domain,
            "severity": iocs["suspicious_domains"][domain]
        })

    if file_hash in iocs["malicious_hashes"]:
        alerts.append({
            "type": "Malicious file hash",
            "indicator": file_hash,
            "severity": iocs["malicious_hashes"][file_hash]
        })

    return alerts

def run_threat_intelligence_check(logs, iocs):
    results = []

    for log in logs:
        alerts = check_log_entry(log, iocs)

        if alerts:
            results.append({
                "timestamp": log["timestamp"],
                "source_ip": log["source_ip"],
                "alerts": alerts
            })

    return results

findings = run_threat_intelligence_check(sample_logs, ioc_database)

for finding in findings:
    print(f"Time: {finding['timestamp']}")
    print(f"Source IP: {finding['source_ip']}")

    for alert in finding["alerts"]:
        print(f"Alert Type: {alert['type']}")
        print(f"Indicator: {alert['indicator']}")
        print(f"Severity: {alert['severity']}")

    print("-" * 40)
```

## Security Value

This module shows how threat intelligence can help defenders identify suspicious activity in logs. Instead of reviewing every log manually, the module highlights entries that match known indicators.

This can help security teams:

- prioritise investigation;
- identify possible compromise;
- detect communication with suspicious infrastructure;
- find possible phishing or malware activity;
- enrich alerts with context;
- respond faster to known threats.

---

## Strengths

The module has several strengths:

- it is simple and easy to understand;
- it supports multiple IOC types;
- it gives severity levels;
- it separates IOC data from log checking logic;
- it can be extended with more indicators;
- it demonstrates a real defensive security concept safely.

---

## Limitations

This is a simplified prototype. Real threat intelligence systems are more complex.

Limitations include:

- no live threat feed integration;
- no automatic IOC updates;
- no confidence score;
- no expiry date for old indicators;
- no false positive handling;
- no integration with SIEM, firewall, or IDS tools;
- no automated response actions;
- fictional sample data only.

Threat intelligence can also become noisy if indicators are outdated or low quality. A match does not always prove compromise, so human review is still required.

---

## Defensive Cybersecurity Discussion

Threat intelligence is most useful when it is timely, relevant, and accurate. A list of indicators alone is not enough. Defenders need context, such as why an indicator is suspicious, how severe it is, and whether it is still active.

This module demonstrates the basic logic behind IOC matching. In a real organisation, similar logic could be used inside a SIEM, IDS, endpoint detection tool, or firewall.

The main defensive value is prioritisation. Security teams often receive large amounts of log data, so threat intelligence can help focus attention on events that are more likely to matter.
