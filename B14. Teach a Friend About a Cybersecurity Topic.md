# B14 - Teach a Friend About a Cybersecurity Topic

## Overview

This entry documents a short cybersecurity teaching activity where I taught **Faiyaz** about ACLs, also known as Access Control Lists.

I chose ACLs because they are a simple and important access control concept. ACLs help decide who can access a resource and what actions they can perform. This makes them useful for understanding permissions, least privilege, and basic system security.

---

## Person Taught

**Faiyaz**

---

## Topic

Access Control Lists (ACLs)

---

## Why I Chose ACLs

I chose ACLs because they are easy to explain using everyday examples. For example, a shared folder can have a list of people who are allowed to read, edit, or delete files. This is similar to how many systems manage access to resources.

ACLs are important in cybersecurity because poor access control can allow unauthorised users to view, change, or delete sensitive information.

---

## Simple Explanation Used

An ACL is a list attached to a resource. The list says which users or groups are allowed to access that resource and what they are allowed to do.

For example:

```text
Resource: shared_report.docx

Alice: read and write
Bob: read only
Charlie: no access
Admin: full control
```

This means Alice can view and edit the document, Bob can only view it, Charlie cannot open it, and the administrator can fully manage it.

---

## Key Ideas Taught

- ACL stands for Access Control List.
- ACLs control who can access a resource.
- ACLs can define different permission levels.
- Common permissions include read, write, execute, delete, and full control.
- ACLs support the principle of least privilege.
- Poor ACL settings can expose sensitive data.
- ACLs are used in file systems, networks, databases, cloud systems, and applications.

## Teaching Dialogue

**me**: Today I want to explain ACLs, which means Access Control Lists.

**Faiyaz**: Okay. I have heard the term before, but I am not completely sure what it means.

**me**: That is fine. An ACL is basically a detailed permission list attached to a file, folder, system, application, or network resource.

**me**: It defines who is allowed to access something, and what actions they are allowed to perform.

**Faiyaz**: So it is similar to sharing permissions on Google Drive or OneDrive?

**me**: Yes, that is a good everyday example. When you share a document, you might give one person permission to view it, another person permission to edit it, and block everyone else.

**Faiyaz**: So the ACL controls different levels of access?

**me**: Exactly. Common permissions include read, write, execute, modify, and delete.

**me**: For example, a student may only be allowed to read a file, a tutor may be allowed to edit it, and an administrator may be allowed to change the permissions.

**Faiyaz**: What does “execute” mean?

**me**: “Execute” means the user is allowed to run a program or script. This matters because a file that looks harmless might actually perform actions on the system if it is executed.

**Faiyaz**: So ACLs are not only about opening files?

**me**: Correct. ACLs can control access to many types of resources, not just documents. They are used in operating systems, databases, cloud platforms, shared drives, routers, firewalls, and enterprise networks.

**Faiyaz**: How would ACLs work in networking?

**me**: In networking, an ACL can be used to allow or block traffic based on rules.

**me**: For example, a firewall ACL might allow HTTPS traffic on port 443 but block Telnet traffic on port 23 because Telnet is insecure.

**Faiyaz**: So ACLs can help block insecure protocols?

**me**: Exactly. A network ACL can stop unsafe protocols, limit access to internal systems, and reduce the chance of attackers moving through the network.

**Faiyaz**: That sounds more serious than normal file sharing.

**me**: It is. ACLs are a core part of cybersecurity because they enforce access control.

**me**: If an ACL is configured badly, users may gain access to information or systems they should not be able to see or change.

**Faiyaz**: Can you give me an example?

**me**: Sure. Imagine a company has a payroll folder. Only HR staff and authorised managers should access it.

**me**: If the ACL accidentally gives “Everyone” read access, then ordinary employees might be able to view salaries, tax details, and personal information.

**Faiyaz**: That would be a serious privacy problem.

**me**: Exactly. Another example is administrator access. A normal user should not have admin-level permissions unless there is a clear reason.

**Faiyaz**: Why is that dangerous?

**me**: Because if that normal user’s account is hacked, the attacker would inherit the same permissions.

**me**: This means the attacker could install malware, delete files, access sensitive systems, or create new accounts.

**Faiyaz**: So the risk is not only the user, but also what an attacker could do with that user’s permissions.

**me**: Exactly. That is why ACLs should follow the principle of least privilege.

**Faiyaz**: What does least privilege mean?

**me**: Least privilege means users should only receive the minimum access they need to complete their work.

**me**: For example, if someone only needs to read a report, they should not be given edit or delete permission.

**Faiyaz**: That makes sense. It limits the damage if something goes wrong.

**me**: Yes. It reduces accidental mistakes and also limits the impact of cyberattacks.

**Faiyaz**: Are ACLs usually given to individual users?

**me**: Sometimes, but in larger organisations, permissions are usually assigned to groups or roles.

**me**: For example, instead of giving access to each employee one by one, a company might create groups such as “HR Staff”, “Finance Team”, “IT Administrators”, and “Students”.

**Faiyaz**: Why is that better?

**me**: It is easier to manage. If a new employee joins the finance team, you add them to the Finance group, and they automatically receive the correct permissions.

**me**: If they leave the team, you remove them from the group, and their access is taken away.

**Faiyaz**: So group-based permissions reduce mistakes?

**me**: Yes. They make access control more consistent and easier to audit.

**Faiyaz**: What does “audit” mean here?

**me**: Auditing means checking who has access, what permissions they have, and whether those permissions are still appropriate.

**me**: For example, a company may review ACLs every few months to remove old accounts, unnecessary access, or permissions that are too broad.

**Faiyaz**: What are some common ACL mistakes?

**me**: Common mistakes include giving too many users admin access, forgetting to remove access after someone changes roles, using broad permissions like “Everyone”, and not reviewing permissions regularly.

**Faiyaz**: So ACLs need ongoing maintenance?

**me**: Exactly. Access control is not something you set once and forget. It needs to be reviewed and updated as users, systems, and security risks change.

**Faiyaz**: What is the main lesson?

**me**: The main lesson is: ACLs help make sure that only the right people can access the right resources, with the right level of permission, for the right reason.

**Faiyaz**: So a good ACL protects confidentiality, prevents unauthorised changes, and limits damage if an account is compromised.

**me**: Exactly. That is a very good summary.

## Example Activity

I gave **Faiyaz** a simple permission scenario:

```text
A university project folder has four users:

- Student A needs to edit the report.
- Student B only needs to read the final report.
- Tutor needs to review and comment.
- Random student should not access the folder.
```

Then I asked **Faiyaz** to assign permissions.

### Expected Answer

```text
Student A: read and write
Student B: read only
Tutor: read and comment/write, depending on the system
Random student: no access
```

---

## Cybersecurity Relevance

ACLs are important because many security problems happen when permissions are too broad. For example:

- a public cloud storage bucket may expose private files;
- a normal user may accidentally receive admin permissions;
- old accounts may keep access after a person leaves a group;
- sensitive documents may be shared with the wrong people.

Strong ACLs help reduce these risks by controlling access carefully.

## Reflection

This activity helped me practise explaining a cybersecurity concept in simple language. I avoided using too many technical terms and used a shared document example to make ACLs easier to understand.

The most important point I explained was least privilege. ACLs are not only about giving access; they are also about limiting access so users do not have more permissions than necessary.

After teaching **Faiyaz**, I understood that ACLs are a useful beginner topic because they connect directly to real systems people use every day, such as shared folders, Google Drive, cloud storage, and university systems.
